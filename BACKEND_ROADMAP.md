# Backend Roadmap

This document defines the proposed backend integration plan for the Ofok Aluminum website and Visual CMS. It is a roadmap only; the current repository remains a frontend application.

## Target Backend Stack

- **Framework:** NestJS
- **Database:** PostgreSQL
- **ORM and migrations:** Prisma
- **API style:** REST with versioned routes under `/api/v1`
- **Validation:** NestJS DTOs with `class-validator` and `class-transformer`
- **Authentication:** Admin-only session using short-lived access tokens and rotating refresh tokens
- **File storage:** S3-compatible object storage
- **API documentation:** OpenAPI/Swagger generated by NestJS

The backend may initially live in a separate repository or in a future monorepo workspace. The frontend should consume it through a configurable API base URL.

## Authentication Plan

- Provide admin login only.
- Do not expose public registration.
- Provision the first admin through a Prisma seed or controlled command.
- Store passwords using Argon2id, with bcrypt as an acceptable fallback.
- Return access and refresh credentials through `httpOnly`, `Secure`, `SameSite` cookies.
- Rotate refresh tokens and store only hashed refresh-token records.
- Add logout, current-session, and refresh endpoints.
- Protect all CMS write endpoints with authentication and authorization guards.
- Support roles such as `SUPER_ADMIN`, `EDITOR`, and `VIEWER` if multiple staff accounts are later required.
- Record successful logins, failed attempts, content changes, and destructive actions in audit logs.

## Security Checklist

- Use Argon2id password hashing and unique salts.
- Store authentication tokens in secure `httpOnly` cookies.
- Rotate refresh tokens and support session revocation.
- Apply authentication and role guards to every admin endpoint.
- Validate and transform every request DTO.
- Reject unknown fields where practical.
- Apply rate limits to login, contact, quote, and upload endpoints.
- Configure a strict CORS allowlist.
- Enable CSRF protection for cookie-authenticated state-changing requests.
- Use Helmet and strict security headers.
- Enforce HTTPS in production.
- Validate uploaded MIME types, extensions, byte signatures, dimensions, and size.
- Generate server-owned storage keys; never trust client filenames as paths.
- Add database constraints, indexes, and transactional writes.
- Keep secrets outside source control.
- Redact credentials and personal data from logs.
- Record audit logs for publishing, updates, deletions, login events, and settings changes.
- Schedule PostgreSQL backups and periodically test restoration.
- Run dependency, container, and migration checks in CI.

## Image Upload Plan

1. The authenticated admin requests a presigned upload from `/admin/media/presign`.
2. The API validates intended MIME type, size, and content category.
3. The frontend uploads directly to object storage using the presigned URL.
4. The frontend calls `/admin/media/confirm` with the storage key.
5. A worker or storage event validates the file and generates optimized WebP/AVIF variants and thumbnails.
6. The API creates a `media_assets` record and returns canonical URLs and metadata.
7. CMS records reference `media_assets.id` instead of accepting arbitrary external URLs.
8. Deletion checks references before removing an asset and its variants.

Recommended limits:

- Images: JPEG, PNG, WebP, or AVIF; maximum 5 MB before processing.
- Quote attachments: PDF and approved drawing formats; maximum size defined separately.
- Strip unsafe metadata where appropriate.
- Serve public assets through a CDN.

## Free Development Infrastructure

Suitable free or local options during development:

- **API:** Local NestJS process or Render/Railway free development allowance where available.
- **PostgreSQL:** Local Docker PostgreSQL, Neon free tier, or Supabase free tier.
- **Object storage:** Local MinIO, Cloudflare R2 development usage, or Supabase Storage free tier.
- **Email testing:** Mailpit locally or Resend development allowance.
- **API testing:** Bruno, Insomnia, or Postman free usage.
- **CI:** GitHub Actions free allowance for private or public repositories according to account limits.
- **Monitoring:** Local structured logs and Sentry's free development tier.

Free-tier availability and quotas change over time and must be verified before selection.

## Paid Production Infrastructure

A practical production setup:

- **Frontend:** Vercel, Cloudflare Pages, or a managed static host.
- **NestJS API:** AWS ECS/Fargate, Fly.io, Render, Railway, DigitalOcean App Platform, or a managed Kubernetes environment when scale requires it.
- **PostgreSQL:** AWS RDS, Neon paid plan, Supabase paid plan, or another managed PostgreSQL provider with point-in-time recovery.
- **Object storage and CDN:** AWS S3 plus CloudFront or Cloudflare R2 plus Cloudflare CDN.
- **Email:** AWS SES, Resend, Postmark, or SendGrid.
- **Secrets:** Cloud-provider secrets manager or encrypted platform environment variables.
- **Monitoring:** Sentry plus provider metrics, centralized logs, uptime checks, and alerting.
- **Backups:** Automated database backups, object versioning where required, and documented restore procedures.

Provider selection should consider deployment region, Palestinian and regional network latency, support requirements, data residency, budget, and operational experience.

## Deployment Phases

### Phase 1: Backend Foundation

- Scaffold NestJS application.
- Configure environment validation.
- Connect PostgreSQL and Prisma.
- Add migrations, seeds, health checks, logging, and Swagger.

### Phase 2: Authentication and Authorization

- Create admin tables and seed command.
- Implement login, refresh, logout, and current-session endpoints.
- Add cookie security, guards, roles, rate limiting, and audit logging.

### Phase 3: Read-Only Content API

- Model sections and content entities.
- Import current static frontend data.
- Implement public published-content endpoints.
- Connect frontend reads while retaining safe fallback data during migration.

### Phase 4: Visual CMS Persistence

- Implement admin CRUD endpoints.
- Connect visual editor save actions.
- Add draft/published status, ordering, validation, and optimistic UI handling.
- Enforce English and Hebrew production content requirements.

### Phase 5: Leads and Settings

- Persist contact messages and quote requests.
- Add inbox status workflows and settings endpoints.
- Integrate transactional email notifications.

### Phase 6: Media Pipeline

- Add presigned uploads, validation, processing, thumbnails, CDN delivery, and cleanup.
- Connect project, product, gallery, partner, and quote attachment workflows.

### Phase 7: Production Hardening

- Add automated tests and CI checks.
- Perform security review and load testing.
- Configure backups, monitoring, alerting, CORS, domains, TLS, and deployment rollback.
- Complete staging acceptance before production release.
